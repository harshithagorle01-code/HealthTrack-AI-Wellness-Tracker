## 8. Target Domains & Categorization

The system operates across 8 core health domains:

1. **Hydration:** Water intake tracking (ml / fluid oz / glasses).
2. **Physical Activity:** Step counts, active exercise duration (minutes), estimated caloric burn (kcal).
3. **Sleep Quality:** Total sleep duration (hours), sleep quality rating (1–5 scale).
4. **Cardiovascular:** Resting heart rate (BPM), blood pressure (systolic/diastolic - optional log).
5. **Body Composition:** Weight (kg/lbs), height (cm/ft-in), BMI (auto-calculated).
6. **Nutrition:** Daily total caloric intake (kcal), macro split estimates (Protein, Carbs, Fats).
7. **Psychological Well-being:** Mood state (Emoji / 5-point ordinal scale), perceived stress index (Low, Medium, High).
8. **Pharmacological / Supplementation:** Medication reminders and adherence logging.

## 9. Form & Advisory Configuration

### Daily Wellness Score Calculation Algorithm

The Daily Wellness Score ($S \in [0, 100]$) is computed server-side or via dynamic utilities as a weighted sum of 5 baseline habits against personalized user daily goals:

$$S = (W_{\text{water}} \cdot 0.20) + (A_{\text{exercise}} \cdot 0.25) + (S_{\text{sleep}} \cdot 0.25) + (P_{\text{steps}} \cdot 0.20) + (M_{\text{mood}} \cdot 0.10)$$

Where each component score is capped at $100\%$:

* $W_{\text{water}} = \min\left(100, \frac{\text{Logged Water}}{\text{Goal Water}} \times 100\right)$
* $A_{\text{exercise}} = \min\left(100, \frac{\text{Logged Exercise Min}}{\text{Goal Exercise Min}} \times 100\right)$
* $S_{\text{sleep}} = \min\left(100, \frac{\text{Logged Sleep Hours}}{\text{Goal Sleep Hours}} \times 100\right)$
* $P_{\text{steps}} = \min\left(100, \frac{\text{Logged Steps}}{\text{Goal Steps}} \times 100\right)$
* $M_{\text{mood}} = \text{Mood Rating (1 to 5)} \times 20$

### Mandatory Non-Medical Disclaimer

Every page footer, AI interaction modal, and generated report MUST continuously render this standardized notice:

> **Health Disclaimer:** *HealthTrack AI is designed exclusively for general wellness tracking and personal habit awareness. It is not a medical device, nor does it provide medical advice, diagnosis, or clinical treatment recommendations. Always seek the advice of a qualified healthcare provider regarding any medical condition.*

## 10. Database Schema (Production SQL for PostgreSQL)

Execute the following DDL script to instantiate the system schema:

```sql
-- Enable UUID extension
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- USERS TABLE
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    age INT CHECK (age > 0 AND age < 120),
    gender VARCHAR(20) DEFAULT 'unspecified',
    height_cm NUMERIC(5,2) CHECK (height_cm > 0),
    weight_kg NUMERIC(5,2) CHECK (weight_kg > 0),
    activity_level VARCHAR(30) DEFAULT 'moderate', -- sedentary, light, moderate, active, very_active
    theme_preference VARCHAR(10) DEFAULT 'dark',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- USER GOALS TABLE
CREATE TABLE goals (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    goal_type VARCHAR(50) NOT NULL, -- water_ml, steps, exercise_min, sleep_hrs, weight_kg, calories_kcal
    target_value NUMERIC(10,2) NOT NULL CHECK (target_value > 0),
    current_value NUMERIC(10,2) DEFAULT 0 CHECK (current_value >= 0),
    start_date DATE NOT NULL DEFAULT CURRENT_DATE,
    end_date DATE,
    status VARCHAR(20) DEFAULT 'active' CHECK (status IN ('active', 'completed', 'abandoned')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- DAILY HEALTH RECORDS TABLE
CREATE TABLE health_records (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    date DATE NOT NULL DEFAULT CURRENT_DATE,
    water_ml INT DEFAULT 0 CHECK (water_ml >= 0),
    steps INT DEFAULT 0 CHECK (steps >= 0),
    exercise_minutes INT DEFAULT 0 CHECK (exercise_minutes >= 0),
    sleep_hours NUMERIC(4,2) DEFAULT 0 CHECK (sleep_hours >= 0 AND sleep_hours <= 24),
    heart_rate_bpm INT CHECK (heart_rate_bpm IS NULL OR (heart_rate_bpm > 30 AND heart_rate_bpm < 250)),
    weight_kg NUMERIC(5,2) CHECK (weight_kg IS NULL OR weight_kg > 0),
    calories_consumed INT DEFAULT 0 CHECK (calories_consumed >= 0),
    mood VARCHAR(20) CHECK (mood IN ('very_sad', 'sad', 'neutral', 'happy', 'very_happy')),
    stress_level VARCHAR(20) CHECK (stress_level IN ('low', 'medium', 'high', 'extreme')),
    wellness_score INT DEFAULT 0 CHECK (wellness_score >= 0 AND wellness_score <= 100),
    notes TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT unique_user_daily_record UNIQUE (user_id, date)
);

-- REMINDERS TABLE
CREATE TABLE reminders (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(100) NOT NULL,
    category VARCHAR(50) NOT NULL, -- water, exercise, sleep, medication, break
    time_of_day TIME NOT NULL,
    frequency VARCHAR(30) DEFAULT 'daily', -- daily, weekdays, weekends, custom
    is_enabled BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- AI INSIGHTS CACHE TABLE
CREATE TABLE ai_insights (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    insight_type VARCHAR(50) NOT NULL, -- daily_summary, weekly_digest, habit_recommendation
    content JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- INDEXES FOR FAST QUERYING
CREATE INDEX idx_health_records_user_date ON health_records(user_id, date DESC);
CREATE INDEX idx_goals_user_status ON goals(user_id, status);
CREATE INDEX idx_reminders_user_enabled ON reminders(user_id, is_enabled);

```

## 11. Row Level Security (RLS) / Data Isolation Rules

To protect health data privacy across sessions:

1. **Application-Level Isolation:** All Express middleware must extract `req.user.id` from validated JWT tokens or encrypted sessions.
2. **SQL Context Safeguard:** Every single database query operating on `health_records`, `goals`, `reminders`, or `ai_insights` MUST explicitly restrict execution using `WHERE user_id = $1`.
3. Direct ORM or Raw Query Parametrization is mandatory. String concatenations in SQL statements are strictly forbidden.
4. Attempting to access, modify, or delete records matching an ID not owned by `req.user.id` must trigger an immediate HTTP `403 Forbidden` response and an internal security audit log.

## 12. Backend API Routes

All API endpoints reside under `/api/v1` and enforce `application/json` payloads.

### Authentication Routes (`/api/v1/auth`)

* `POST /register` - Validate input, hash password with `bcryptjs` (salt rounds = 12), insert user, return JWT token and user profile object.
* `POST /login` - Validate credentials, return JWT token.
* `POST /logout` - Invalidate session/cookie.
* `GET /me` - Return currently authenticated user profile.

### User Profile & Goals Routes (`/api/v1/user`)

* `PUT /profile` - Update bio-metrics, goals, and targets.
* `GET /goals` - Fetch active and historical user goals.
* `POST /goals` - Create a new health goal target.
* `PUT /goals/:id` - Update goal target or status.
* `DELETE /goals/:id` - Remove a goal.

### Health Records Routes (`/api/v1/records`)

* `GET /` - Fetch paginated daily logs (supports query params `startDate`, `endDate`, `limit`).
* `GET /today` - Fetch or initialize today's daily record for the current user.
* `POST /` - Insert or Upsert (`ON CONFLICT (user_id, date) DO UPDATE`) today's log. Automatically recalculates `wellness_score`.
* `PATCH /increment` - Quick-increment a specific metric (e.g., `{ metric: "water_ml", delta: 250 }`).
* `DELETE /:id` - Erase a health record entry.

### Analytics Routes (`/api/v1/analytics`)

* `GET /summary?range=7d|30d|90d` - Aggregate metric averages, total volume, trajectory percentages, and score distribution.

### Reminders Routes (`/api/v1/reminders`)

* `GET /` - List user reminders.
* `POST /` - Create a reminder entry.
* `PUT /:id` - Update status/timing.
* `DELETE /:id` - Delete a reminder.

### AI Assistant Routes (`/api/v1/ai`)

* `GET /daily-insight` - Fetch or trigger today's Gemini 2.5 structured wellness insight.
* `POST /chat` - Stream or respond to contextual wellness Q&A based on recent 14-day history.
* `GET /weekly-digest` - Synthesize historical data into an actionable weekly report.
